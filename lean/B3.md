## Key finding: no new Lean machinery for the cover
`CombNumerics` is the CHAIN statement (N(v) < 2 w_1 S cos(theta_1/2) for each v in V, V contains cvec(P1, u) for all u in [0,1)).
It does not depend on the u-cells. So the Python 1024-cell cover, the 8 ambiguous cells (1032 combinations) and "per-cell weight vectors"
are NOT needed in Lean: the weight vector is ONE vector for all cells (cert: "single vector, all cells"), and the ambiguous-floor cases are
exactly the chain breakpoints, covered by `chain_mem` (case split on u against 7 thresholds, 8 leaves).
The closed form fails for 622 (R = 1.0179) but the chain check passes: MEASURED in Python (`gen622.py --full`, 4 min, all 2000 zeros, exact integer
arithmetic): max R per chain vector 0.9833 (worst vector 1), margin 1.7 percent; min chain gap 0.044 (711: 1e-3), so the P1 precision needed is far looser.
`M P_1 <= 622` follows from `P_bounds` (P <= 88.848139, 7 x = 621.937), no new zero-1 lemma; `zero1_facts` (theta>0, <pi/2, cos(theta/2) >= 0.99936) is reused as is
(its `8 (2pi/theta) <= 711` conjunct is simply unused).
